# QR 팔찌 발권 전용 화면

2026-11-11 · 하드웨어 검증 전 시험판

관리자 로그인 후 `/field/issuance`에서 사용한다. 현장 매표소에 진입 버튼을 추가했으며 고객 홈페이지·예약·결제 디자인은 변경하지 않았다. 백엔드 저장소의 `codex/qr-wristband-desk` 변경과 함께 적용해야 한다. 이 프런트만 배포하면 발권 API가 동작하지 않는다.

전용 모듈은 `wristband-layout.js`(선인쇄 250×25mm 가변정보), `wristband-engine.js`(발권/오류 복구), `wristband-desk.js`(창구 화면), `wristband-desk.css`이다. 실물 출력은 Windows 연결 프로그램 127.0.0.1:17864에 요청한다.

처음에는 시험 예약·모의 출력이며 발권 시작을 체크한 뒤 새 예약을 스캔해야 자동 진행한다. 실제 예약은 서버 결제 확인과 Windows 프린터 연결이 필요하다. 재스캔은 자동 재출력하지 않는다. 출력 요청과 결과가 불확실한 경우 직원이 Windows 대기열을 정리하고 기존 팔찌를 회수한 뒤 사유를 남겨 재출력한다.

기존 홈페이지를 수정하지 않고 신규 전용 CSS를 `.wd-root` 아래로 제한했다. 실제 브라우저 화면/Windows 실기 검증은 현장에서 진행해야 한다. DOM 통합 시험과 인쇄 이미지 렌더링 검증, 기존/신규 자동 시험, 빌드는 완료했다. 서버 상태가 accepted여도 실물 완료를 뜻하지 않는다.

`npm test`, `npm run build`로 검증한다. 상세 배포 순서와 후퇴 절차는 백엔드 `docs/QR_WRISTBAND_DEPLOYMENT.md`를 따른다. 새 방식으로 발권한 기록이 생긴 뒤에는 백엔드 중복 방지 가드를 제거하지 않는다.
