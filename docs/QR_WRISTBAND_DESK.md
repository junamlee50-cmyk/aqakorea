# QR 팔찌 발권 전용 화면

2026-11-15 · 하드웨어 검증 전 시험판

관리자 로그인 후 `/field/issuance`에서 사용한다. 현장 매표소에 진입 버튼을 추가했으며 고객 홈페이지·예약·결제 디자인은 변경하지 않았다. 백엔드 저장소의 `codex/qr-wristband-desk` 변경과 함께 적용해야 한다. 이 프런트만 배포하면 발권 API가 동작하지 않는다.

전용 모듈은 `wristband-layout.js`(선인쇄 250×30mm 가변정보), `wristband-engine.js`(발권/오류 복구), `wristband-desk.js`(창구 화면), `wristband-desk.css`이다. 실물 출력은 Windows 연결 프로그램 127.0.0.1:17864에 요청한다.

처음에는 시험 예약·모의 출력이다. 기본적으로 예약번호·일시·인원·프린터 확인창을 거쳐 출력하며, QR 즉시 출력은 직원이 별도로 켠 경우에만 확인창을 생략한다. 실제 예약은 서버 결제 확인과 Windows 프린터 연결이 필요하다. 재스캔은 자동 재출력하지 않는다. 출력 요청과 결과가 불확실한 경우 직원이 Windows 대기열을 정리하고 기존 팔찌를 회수한 뒤 사유를 남겨 재출력한다.

기존 홈페이지를 수정하지 않고 신규 전용 CSS를 `.wd-root` 아래로 제한했다. 실제 브라우저 화면/Windows 실기 검증은 현장에서 진행해야 한다. DOM 통합 시험과 인쇄 이미지 렌더링 검증, 기존/신규 자동 시험, 빌드는 완료했다. 서버 상태가 accepted여도 실물 완료를 뜻하지 않는다.

`npm test`, `npm run build`로 검증한다. 상세 배포 순서와 후퇴 절차는 백엔드 `docs/QR_WRISTBAND_DEPLOYMENT.md`를 따른다. 새 방식으로 발권한 기록이 생긴 뒤에는 백엔드 중복 방지 가드를 제거하지 않는다.

## 2026-11-15 발권 실수 방지

- 예약 관리의 `발권·출력`은 예약번호를 채운 전용 화면으로 이동만 한다. 기존 DB 발급 API를 직접 호출하지 않는다. 현장 부여 발권도 같은 경로를 사용한다.
- 프린터 연결 실패는 발권 작업 생성 전에 차단한다. 전송 이후 장애는 미전송/실패/결과 불확실 상태로 남는다.
- Windows 전송 성공은 `인쇄 대기열 전송 · 실물 확인 전`이다. 예약 인원 전원이 accepted 상태인 뒤 직원이 `실물 확인 · 발권완료 처리`를 누르면 서버가 예약·인원·결제·현재 출력 시도를 다시 검사하여 checkedin/active 처리한다.
- `발권 되돌리기`는 지역/총괄관리자에게만 허용한다. 사유와 미탑승·대기열 정리·팔찌 회수 확인이 필요하며 예약·결제·금액·인원을 유지한다. 기존 팔찌는 무효화하고 처리 이력을 남긴다. 이미 탑승한 예약이나 출력 결과가 불확실한 예약은 차단한다.
- 되돌린 새 발권 작업은 재스캔해도 자동 재출력하지 않는다. 내역에서 인원별 `재출력 검토`를 거쳐 새 출력 ID로 처리한다.
- `예약 취소`는 별도 사유·확인을 요구한다. 서버 실패를 성공으로 표시하거나 행의 잘못된 칸을 바꾸지 않는다. 실제 환불은 실행하지 않는다. 이미 취소된 예약을 자동 복원하지 않는다.
- 프런트 20개·서버 31개 자동시험 통과. 서버는 Node 24 SQLite와 Node 20 better-sqlite3 양쪽 검증. DOM+HTTP 시험에서 모의 인쇄와 대체 인쇄 함수 호출, 중복 차단, 재출력 확인. 실제 Windows 인쇄와 30×250mm 밴드 정합은 미검증.
- 운영 반영 전 백엔드와 프런트를 함께 검증/배포하고 PC 연결 프로그램을 설정해야 한다. 현재 운영 DB에는 수정 시험을 실행하지 않았다.

## 고객 QR·예약 상세 연결 보완 (2026-11-15)

예약 상세에 팔찌 발권·출력과 고객 QR 탑승권 보기를 구분했다. QR 화면의 전체 웹페이지 인쇄를 제거하고, 관리자용 출력 버튼은 전용 발권 화면으로 이동한다. 관리자 QR 화면의 뒤로 버튼은 해당 예약 상세로 복귀한다. qrcodejs와 맞지 않는 `toCanvas` 호출 및 canvas 컨테이너를 수정하여 QR 공백 문제를 해결했다. 실제 번들 라이브러리로 비어 있지 않은 QR 렌더링을 검증했다.

예약 상세는 `/api/reservation-notifications/:id`로 문자/알림톡 상태를 조회한다. QR은 문자 URL 또는 알림톡 버튼으로 열며, 손목밴드에는 QR을 인쇄하지 않는다. 미결제 예약은 '예약접수 · 결제 대기'로 표시한다. 백엔드 환경설정·템플릿 승인·운영 전 검수는 aqakorea-server의 `docs/RESERVATION_NOTIFICATIONS.md` 참조.

검증: 프런트 22개 테스트, 백엔드 42개 테스트. 실제 Windows 출력과 휴대폰 수신은 미검증이며 운영 배포와 별개의 항목이다. 기존 홈페이지 배색/구성은 이번 수정 대상이 아니다.

## 직접 주소 접속 404 보완 (2026-11-15 추가)

운영 반영 보고에서 `/field/issuance` 직접 접속이 404인 점을 재현할 수 있는 코드 누락을 확인했다. 이 앱은 해시 라우터가 아니라 History API를 사용한다. 서버에 `/field`만 있고 `/field/dashboard`, `/field/issuance`가 빠져 있었으며, 초기 화면 결정도 field/admin 하위 경로를 메인 화면으로 바꾸고 있었다.

- `src/index.tsx`: 등록된 현장 경로 3개에 앱 문서를 제공한다. 임의 `/field/*`를 모두 성공 처리하지 않는다.
- `public/static/app.js`: 현장·관리자 직접 접속/새로고침 시 원래 경로와 쿼리를 유지한다. 로그인 가드는 유지한다.
- `/field/scan`은 현재 프런트 라우터에도 등록되어 있지 않다. 이 주소의 404를 발권 화면 404가 정상이라는 근거로 삼으면 안 된다.
